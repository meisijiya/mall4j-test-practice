4.1 概念 1：POM 7 类架构（BasePage + 6 业务 Page + LoginPage 双端口）

2 个 mock 静态方法核心代码（common/ui_pages.py 内）：

@staticmethod
def mock_captcha_route(page) -> None:
    """拦截 captcha 端点，返回 mock 响应让前端组件跳过滑块交互。

    关键：**必须在 page.goto 之前注册**，否则浏览器先发起真实网络请求。
    """
    import json

    def handle_captcha(route) -> None:
        route.fulfill(
            status=200,
            content_type="application/json",
            body=json.dumps({
                "code": "00000",
                "msg": "success",
                "data": {"captchaVerification": "mock_captcha_token_for_test"},
            }),
        )

    page.route("**/captcha/**", handle_captcha)


@staticmethod
def mock_login_response(page, mock_token: str = "mock_token_for_test") -> None:
    """拦截 adminLogin / login 端点，返回 mock Sa-Token 响应。

    关键：**mock 的是 /adminLogin，不是 /login** —— mall4v 前端
    login/index.vue:118-127 走 /adminLogin（即使是普通用户登录）。
    """
    import json

    def handle_login(route) -> None:
        route.fulfill(
            status=200,
            content_type="application/json",
            body=json.dumps({
                "code": "00000",
                "msg": "success",
                "data": {
                    "accessToken": mock_token,
                    "refreshToken": "mock_refresh_token",
                    "expiresIn": 86400,
                },
            }),
        )

    page.route("**/adminLogin", handle_login)
    page.route("**/login", handle_login)   # 双保险
路径 2 金句
"路径 2 = 真实填表单 + mock 后端"——路径 1 是"API 拿 token + cookie 注入 + 跳首页"（绕滑块）；路径 2 是"page.route 拦截 + 真实 fill / click + 跳首页"（保留前端流程）。两者互补：路径 1 验证"后端鉴权 → cookie → 前端路由"；路径 2 验证"前端表单 → mock 后端 → 前端路由"。简历硬数字写"Playwright Page Object + UI mock + 真实交互"就是路径 2 的功劳。

4.3 概念 3：admin vs shop 双 selectors dict（Element Plus vs mall4v Verify）

def fill_form(self, username: str, password: str, *, port: str = "shop") -> None:
    """双端口填表单 —— 按 port 参数选 selectors。"""
    if port not in ("shop", "admin"):
        raise ValueError(f"port 必须是 shop 或 admin，当前: {port}")

    sel = self.selectors[port]   # 关键：dict 双 key 切换
    self.fill(sel["username"], username)
    self.fill(sel["password"], password)


def click_submit(self, *, port: str = "shop") -> None:
    """双端口点登录 —— 按 port 参数选 selector。"""
    sel = self.selectors[port]
    self.click(sel["submit"])

"5 helper + pytest.ini marker 双兼容"——allure_compat.severity_normal() 没装 allure-pytest 时是 noop；pytest.ini 加 severity marker 解决 pytest 8.x PytestUnknownMarkWarning。两个修法必须同时做——只做 (a) 没 allure 时 marker 报 unknown；只做 (b) 装了 allure 时 marker 不进报告。

D8 不直接复制 D7 风格的 4 个原因：

  1. 每个 Controller 一套 yaml——register_data.yaml 只含 register 端点 4 条；不混到 user_data.yaml。便于横向对比（register 失败只看 register_data.yaml）。
  2. API wrapper 独立文件——api/register_api.py 只含 2 个方法（register + send_sms）；不混到 user_api.py。便于单元测试 + mock 替换。
  3. testcases 独立文件——test_register.py 只参数化 4 条 register 用例；不混到 test_user.py。便于按 Controller 单独跑（如 pytest test_register.py）。
  4. 业务码字符串断言——沿用 L11 §4.2 五业务码模板（'00000' / 'A00001' / 'A00004' / 'A00005' / 'A00014'），不传 Integer 200（D7 已修的 bug 别再踩）。
