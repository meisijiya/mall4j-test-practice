1. 为什么测试需要性能压测（功能 PASS ≠ 性能 PASS）

功能测试 150 用例全 PASS 不代表 100 用户同时下单还能跑通。性能压测回答的问题：

  • TPS（Transactions Per Second）：每秒处理请求数，越高越好
  • P95/P99 延迟：95% / 99% 请求在该时间内完成（不是平均值）
  • 错误率：失败请求 / 总请求，越低越好（一般 <1%）
  • 拐点：用户数从 50 涨到 100，TPS 反而下降 → 找到系统极限

反例：某电商促销日 100 万用户同时下单 → JVM full GC → 30 分钟没人能结账。

2. Locust 基础（HttpUser + @task + on_start + wait_time）

2.1 四个核心概念

from locust import HttpUser, task, between, events

class Mall4jUser(HttpUser):
    wait_time = between(1, 3)   # 每个任务间 1-3 秒（模拟真实用户思考）
    weight = 1                  # 多 User 类时的权重比

    def on_start(self):
        """每个虚拟用户启动时调用一次（登录拿 token）"""
        resp = self.client.post("/adminLogin", json={...})
        self.token = resp.json()["data"]["accessToken"]

    @task(60)                    # 权重 60/100 = 60% 概率执行
    def view_prod_list(self):
        self.client.get("/prod/prodList", headers={"Authorization": self.token})

    @task(30)                    # 权重 30/100 = 30%
    def view_prod_detail(self):
        self.client.get("/prod/prodInfo?prodId=1")

    @task(10)                    # 权重 10/100 = 10%
    def view_my_info(self):
        self.client.get("/p/user/info")

2.2 两种运行模式

# 模式 1：Web UI（开发调参用）
locust -f locustfile.py --host=http://127.0.0.1:8086
# 浏览器打开 http://localhost:8089 → 输入用户数 / spawn_rate / run_time

# 模式 2：Headless（CI / 自动化用）
locust -f locustfile.py \
    --host=http://127.0.0.1:8086 \
    --users 100 --spawn-rate 10 --run-time 60s \
    --headless --only-summary \
    --html reports/locust-report.html \
    --csv reports/locust-stats

2.3 stats 报告字段含义

  • # Requests：总请求数
  • # Fails：失败请求数
  • Median：中位数延迟（ms）
  • 95%ile / 99%ile：P95 / P99 延迟
  • Average：平均延迟
  • Min / Max：最快 / 最慢请求
  • Average size：平均响应字节数
  • Current RPS：当前每秒请求数
  • Current Failures/s：当前每秒失败数

3. mall4j 100 用户压测设计（3 任务权重 + AES 复用）

M3-D10-001 落地的 locustfile.py 设计：

  1. on_start adminLogin：每个虚拟用户启动时调 /adminLogin 拿 token；密码用 lesson 0012 复用的 encrypt_password（key='-mall4j-password' + salt=Date.now()）
  2. @task(60) view_prod_list：商品列表查询（GET /prod/prodList?page=1&size=20）—— 60% 权重
  3. @task(30) view_prod_detail：商品详情（GET /prod/prodInfo?prodId=1）—— 30% 权重
  4. @task(10) view_my_info：个人信息（GET /p/user/info）—— 10% 权重
  5. wait_time between(1, 3)：每个任务间 1-3 秒模拟真实用户

为什么 60/30/10 而不是 33/33/33？ 真实用户行为分布：浏览商品列表最多（60%）→ 看商品详情次之（30%）→ 进入个人中心最少（10%）。权重反映真实流量分布。

4. 6 件非显然 fix + 报告解析（CSV → markdown）

  1. AES 复用 lesson 0012 — sys.path.insert(0, '../api-auto') + from common.mall4j_aes import encrypt_password；不要重写 AES（密码 16 字节 key + 13 字节盐 + ECB + Pkcs7 是 mall4j 后端 PasswordManager 兼容的反向格式）
  2. try/except ImportError 优雅降级 — locust 仅实跑必需；agent 沙箱没装 locust 也能 ast.parse 验证通过，import 时 fallback 到 stub（HttpUser=object / task=lambda）
  3. adminLogin 路径而非 /login — mall4j 后端 LoginController.java:51 走 /adminLogin（不是 /login）；lesson 0009 已踩过这个坑二次提醒
  4. Windows Git Bash 必须 GEVENT_BACKEND=select — 默认 libuv backend 在 Windows 上有兼容问题；run-locust.sh 第一行 export GEVENT_BACKEND=select
  5. NUM_USERS=100 顶部常量 — 不用命令行 --users 100；脚本顶部 NUM_USERS=100 / SPAWN_RATE=10 / RUN_TIME="60s" 三个常量，便于 CI 通过环境变量覆盖
  6. CSV 解析用 csv.DictReader — Locust 输出 --csv-prefix 产物是 _stats.csv + _failures.csv + _history.csv + _distribution.csv 四件；generate-locust-report.py 用 DictReader 解析 stats.csv 生成 markdown 报告

4.1 报告解析（generate-locust-report.py 输出 markdown）

import csv
from pathlib import Path

REPORTS = Path("reports")
stats = []
with (REPORTS / "locust-stats.csv").open(encoding="utf-8") as f:
    for row in csv.DictReader(f):
        if row["Name"] and row["Name"] != "Aggregated":
            stats.append(row)

# 输出 markdown：每个 endpoint 一行表格
for s in stats:
    print(f"| {s['Name']} | {s['# Requests']} | {s['# Fails']} | "
          f"{s['Median']}ms | {s['95%']}ms | {s['99%']}ms | "
          f"{s['Average']}ms |")

4.2 异常阈值标注

  • TPS < 30 → 单实例 Spring Boot 极限，警告"考虑分布式"
  • P99 > 2000ms → 单接口性能瓶颈，警告"考虑缓存/索引"
  • 错误率 > 1% → mall4j 服务端异常，警告"检查后端日志"

5. 思考题 + 下一课

Q1：Locust 中 @task(60) 与 @task(30) 同时存在，单次循环执行哪个？答：按权重随机选择（60% 概率选 task(60)，30% 概率选 task(30)，10% 概率选 task(10)）

Q2：on_start 与 @task 的执行顺序？答：每个虚拟用户实例化时先调一次 on_start（登录），之后才开始循环执行 @task；on_start 失败 token 为空 → 后续 @task 走未鉴权路径

Q3：100 用户 60s 实跑后 stats.csv 的"Current RPS"字段含义？答：实跑最后一秒的瞬时 RPS，不是平均值；想看平均 RPS 用 # Requests / run_time 公式计算
