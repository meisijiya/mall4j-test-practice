# 第 1 课：mall4j 业务全貌——B2C 单商户电商 + 三端合一 + 五流贯通

> **本课 Mission**：5 分钟讲清楚 mall4j 是什么、为什么测它、测哪些面。
> **读者画像**：双非本科大四 / Java + Python 基础 / 零实习 / 主攻测开。
> **本课范围**：只讲业务理解，不写代码。代码层细节留给后续课程。

---

## 1. 一句话定位

mall4j 是 **B2C 单商户电商开源系统**，前后端分离，一套后端同时支撑管理后台、小程序、uni-app 三端前端，业务闭环覆盖商品 → 购物车 → 订单 → 支付 → 后台发货 → 数据统计全链路。

来源：`doc/1-项目概览/1-项目介绍.md` 第 3 行：*"Mall4j 开源版是一个 Java B2C 单商户商城系统，采用前后端分离架构。"*

## 2. 为什么是 mall4j（简历可写理由）

来自 `D:/26测试/PROJECT_TARGET_BOOK.md` v3.0 选型论证：

| 维度 | mall4j 的数据 | 简历卖点 |
|---|---|---|
| 业务清晰度 | B2C 电商，覆盖商品/订单/支付/购物车/会员/权限 | "电商系统全链路测试"可写 |
| 技术栈主流度 | Spring Boot + Vue3 + Sa-Token + MyBatis-Plus + Redis + Redisson | 测开岗主流栈全覆盖 |
| 文档完备度 | 官方 30 分钟启动路线 + 二开指南 + 数据模型 | 学习成本低 |
| 社区活跃度 | ⭐5.2k + 🍴1.3k + 2026-09 仍在更新 | 不怕被问"项目还活着吗" |
| 测试覆盖度 | Swagger 完备 + admin 后台 + Web 前端 = 4 件套全覆盖 | 一份项目支撑功能/UI/接口/性能 |

**面试官一句话总结**：选 mall4j 是因为它业务真实、体量扛得住深问、技术栈主流、文档够自学，能在 14 天内做出"做深+扛追问"的作品集。

**反问预案**：为什么不用 mall-cook（配置复杂，14 天跑不通）/ 为什么不用自研 CRUD（star 太低，面试官会追问）。

## 3. 三端架构：管理后台 / 用户端 / 移动端

来源：`doc/1-项目概览/3-后端模块说明.md`

```text
                ┌─────────────────────────────┐
                │   yami-shop-admin  :8085    │
                │   (管理后台后端)            │
                └──────────────┬──────────────┘
                               │
                ┌──────────────▼──────────────┐
                │   yami-shop-api    :8086    │
                │   (用户端后端)              │
                └──────────────┬──────────────┘
                               │
        ┌──────────────┬───────┴────────┬──────────────┐
        ▼              ▼                ▼              ▼
   管理后台前端     小程序前端       H5 移动端      uni-app 前端
   front-end/      front-end/      front-end/      front-end/
   mall4v          mall4m          mall4m          mall4uni
   (Vue3+Vite)     (微信小程序)     (H5)            (跨端编译)
```

**两个后端入口**：

| 后端模块 | 端口 | 调用方 |
|---|---|---|
| `yami-shop-admin` | 8085 | 管理后台 `front-end/mall4v` |
| `yami-shop-api` | 8086 | 小程序 `front-end/mall4m` / H5 / uni-app |

**测试含义**：三端调用的是**两套后端接口**，接口契约各管各的。接口自动化必须**分别建两套用例集**，不能合并。

## 4. 五流贯通（资金流 / 信息流 / 物流 / 配置流 / 数据流）

来源：`CONTEXT.md` 第 6-14 行（三流合一）+ 教材延展为五流。

测试用例必须落到流的交叉点，单点通过的孤立测试**不写进用例库**。

| 流 | 起点 | 终点 | 测试切入点 |
|---|---|---|---|
| **资金流** | 支付（微信/支付宝/余额） | 商家结算 → 退款原路返回 | 订单状态机、支付回调幂等、退款链路 |
| **信息流** | 用户下单 | 商家后台看到订单 → 仓库拣货 | 状态同步、消息推送 |
| **物流** | 商家发货 | 用户签收 | 物流公司对接、单号回填 |
| **配置流** | 管理后台配置（商品/角色/菜单） | 用户端行为生效 | 配置热更新、缓存刷新、角色-菜单表 |
| **数据流** | 订单/支付/会员数据 | 统计报表聚合 | SQL 聚合准确性、缓存一致性 |

**反模式示例**：孤立测"商品列表能不能加载"——单点通过但业务不通，**不写进用例库**。

## 5. 核心交易链路（商品/SKU → 购物车 → 确认订单 → 提交订单 → 支付 → 后台发货）

来源：`doc/6-核心业务/1-核心交易链路.md` 第 6 行。

```text
商品/SKU  →  加入购物车  →  确认订单  →  提交订单  →  支付  →  后台订单管理（发货）
```

**每个环节的接口入口**（来自核心交易链路文档第 23-26 行）：

| 环节 | 接口入口类 | 关键方法 |
|---|---|---|
| 商品浏览 | `ProdController`、`SkuController` | 商品和 SKU 读取 |
| 购物车 | `ShopCartController` | 加车/改数/删除/统计 |
| 确认订单 | `OrderController` | `confirm`：生成快照写入 `ConfirmOrderCache` |
| 提交订单 | `OrderController` | `submitOrders`：从缓存创建订单+订单项 |
| 支付 | `PayController` | 生成支付流水 + 更新支付状态 |
| 后台订单 | 管理端 `OrderController` | 查询/详情/发货/导出 |

**关键设计（影响测试）**：
- 确认订单结果先放 `ConfirmOrderCache`，提交时读取。
- 提交订单后**清理确认订单缓存**+购物车下单时清理购物车缓存。
- 支付成功**发布事件**，后续逻辑通过事件扩展——这是性能压测时需要关注的扩展点。

**不建议新手先改的地方**：库存扣减/返还、支付状态流转、订单状态流转、订单自动取消/确认收货——影响交易一致性。

## 6. 七大模块速查

来源：`doc/1-项目概览/1-项目介绍.md` 第 24-28 行 + `CONTEXT.md` 第 19-25 行整合。

| # | 模块 | 核心能力 | 测试侧重 |
|---|---|---|---|
| 1 | **商品 / SKU** | 分类、规格、SKU、库存 | 商品查询、SKU 选择、库存扣减 |
| 2 | **购物车** | 加车、改数、删除、优惠叠加 | 缓存一致性、登录态边界 |
| 3 | **订单** | 确认/提交/状态机/取消 | 状态机、回调幂等、退款 |
| 4 | **支付** | 微信/支付宝/余额 | 支付流水、回调幂等 |
| 5 | **会员** | 注册/登录/地址/等级 | 鉴权链、地址簿边界 |
| 6 | **权限** | 角色、菜单、数据权限 | Sa-Token、角色-菜单过滤 |
| 7 | **统计** | 运营报表聚合 | SQL 准确性、缓存一致性 |

**注意**：开源版第一阶段**不包含**营销、供应链、多商户、SaaS、跨境——面试被问到这些功能时直接说"开源版不支持"。

## 7. 业务理解 → 测试切入映射表

| 业务概念 | 对应测试方法 | 对应测试件 | 简历句子 |
|---|---|---|---|
| 商品/SKU 多规格 | 等价类 + 边界值 | 功能测试用例 | "梳理 XX 模块 XX 个等价类" |
| 购物车加车改数删 | 场景法 + 状态迁移 | 功能 + UI 自动化 | "覆盖购物车 XX 个核心场景" |
| 订单状态机 | 状态迁移图 | 接口自动化 + 边界用例 | "设计订单状态机用例 XX 条" |
| 支付回调 | 幂等性测试 | 接口自动化 + 异常场景 | "验证支付回调幂等性" |
| 角色-菜单权限 | 正交实验 | UI + 接口 | "设计 XX 个角色权限组合用例" |
| 资金流/物流 | 全链路联测 | 接口自动化关联 | "完成加购-下单-支付-发货全链路" |
| 数据流统计 | SQL 直查 + 接口对照 | 接口自动化 | "运营报表准确性校验" |

**求职亮点**：把"业务概念"翻译成"测试方法 + 测试件 + 简历句子"，是测开岗面试的核心能力。
