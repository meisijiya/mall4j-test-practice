6. 5 类高频追问 + 答案框架

6.1 追问 1：为什么选 mall4j 这个项目？

答案框架（3 段）：

  1. 业务贴近：B2C 电商场景，和真实业务最接近，技术栈主流
  2. 体量合适：⭐5.2k star，文档完备，Swagger / API / admin 后台一应俱全，能扛得住深入追问
  3. 避免重复造轮子：不自己写 demo 项目练手，直接基于成熟开源项目做测试实战，产出物可验证

6.2 追问 2：18 个缺陷怎么发现的？

答案框架（3 段）：

  1. 静态分析：读 Controller 注解 + Param 字段约束 + Service 实现 + Security 配置（AGPLv3 边界：仅基于源码静态分析，不改源码）
  2. 业务反推：从状态机推异常路径（如订单从待付款→已取消的退款链路）
  3. 场景组合：多条件组合下未覆盖的角落（如支付超时 + 自动取消 + 库存回滚）

6.3 追问 3：性能瓶颈怎么定位和调优的？

答案框架（3 段定位 + 1 轮调优）：

  1. 看 TPS 拐点：TPS 不再随并发增长 → 瓶颈出现
  2. 看 P99 退化曲线：P99 急剧上升 → 排队/超时
  3. 看错误率类型：连接超时 → 线程池满 / 5xx → 代码问题 / 4xx → 参数问题
  4. 调优决策树：线程池满 → Tomcat threads max 200→400；连接池满 → HikariCP 10→30；缓存连接满 → Lettuce 6→20；GC 频繁 → JVM -Xmx1g + G1GC

6.4 追问 4：接口自动化框架怎么搭的？

答案框架（5 层架构）：

  1. common 层：base_api（HTTP 客户端）+ assertion（5 类业务码）+ AES 加密兼容 + YAML 加载器
  2. data 层：19 个 YAML 文件 / 75+ 用例 / {{var}} 模板替换 / SafeDict 缺 key 兜底
  3. api 层：18 个接口 wrapper 类（每个接口一个方法）
  4. testcases 层：18 个 pytest 文件 / 参数化扩列 / allure 装饰器
  5. 报告层：Allure HTML + severity 分级 + 历史趋势

6.5 追问 5：怎么测试 AI Agent？

答案框架（4 维度）：

  1. 理解 Agent 工作模式：意图理解 → 工具选择 → 执行 → 返回结果（不深问 LangGraph 原理）
  2. 4 个评测维度：事实性（回答准确）/工具选择率（选对工具）/拒答率（不知道时说不知道）/幻觉率（不编造）
  3. 测试用例设计：正常/异常/边界/对抗 4 类，每类至少 8 条
  4. LLM-as-Judge：用大模型当裁判，自动评估输出质量

⚠️ 降级策略：mall4j 鉴权压测如果跑不通 → 说"做了未鉴权压测做基线，鉴权场景写了脚本待接入，核心是 Locust + 阶梯加压方法"。

7. 3 题 quiz 自检

Q1：mall4j 13/13 features done 后，下一步最高优先级是什么？

答案

GitHub 建 3 仓库 + 用 init-repo.sh 三模式填充 + push + 投递简历。M2 即最低可投状态，13/13 完成时更应立即投递。M4 mall-ai 本地跑通是独立项目独立 harness，不在 mall4j 范围。

Q2：简历"覆盖 80+ 核心接口"对应的实际产出是？为什么这样写？

答案

实际产出：pytest --collect-only 90 tests / 19 YAML / 75+ 接口用例。
为什么这样写：① "覆盖 80+" 比 "75" 更稳妥，留 ×2 原则余量；② "核心接口" 暗示是重要业务接口而非全量；③ "覆盖" 动词比 "执行" / "实现" 更符合实习岗定位（参考 PROJECT_TARGET_BOOK §5.1 动词控制表）。

Q3：3 个 GitHub 仓库各自的定位和内容是什么？为什么分 3 个？

答案

mall4j-test-practice：测试设计与产出（用例 + 缺陷 + 报告 + 教学）——证明测试设计能力。
mall4j-auto-test：自动化工具链（接口 + UI + CI + 性能）——证明自动化能力。
agent-eval-practice：AI Agent 评测（方法论 + 用例 + LLM-as-Judge）——证明 AI 测试能力。
为什么分 3 个：① 单一仓库 README 太长，面试官扫读效率低；② 协议不同（mall4j 是 AGPL-3.0，mall-ai 是 Apache-2.0），分开管理避免混淆；③ 能力维度分离：测试设计 / 自动化实现 / AI 测试 是测开岗 3 个核心能力维度。
