## 1. 概述

### 1.1 项目背景
mall4j 是一款 B2C 单商户开源电商系统，本仓库 fork 自官方版本（AGPLv3 协议），包含以下子模块：
- `yami-shop-api`（用户端 API，端口 8086，含 Knife4j Swagger UI `/doc.html`）
- `yami-shop-admin`（管理后台，端口 8085）
- `yami-shop-security-admin`（Sa-Token 鉴权核心）
- `front-end/mall4v` / `mall4uni` / `mall4m`（Vue3 / UniApp / 移动 H5 端）

本测试对象限定为**用户端主链路**（登录 → 加购 → 下单 → 支付 → 收货 → 评价），不含 M4 mall-ai AI Agent 评测模块。

### 1.2 测试目标
- 验证 **三流合一**（资金流 + 信息流 + 物流）主链路在用户端的功能正确性
- 验证鉴权链（无 token / token 过期 / 角色越权 / 多角色菜单过滤）4 类场景
- 验证幂等性（订单号 / 支付回调 / 退款请求）3 类场景
- 暴露 18 个缺陷，按严重等级归档
- 形成首份可向 PM / 开发汇报的功能测试报告

### 1.3 测试范围

**In-scope**：
| 模块 | 用例数 | 备注 |
|---|---|---|
| 登录 / 注册 | 40 | D2 已完成 |

**Out-of-scope**：

- 后台高级权限（如超管分库分表、审计日志回溯）

## 8. 测试结论

### 8.1 是否达到发布标准
**建议（待回填）**：根据 4.5 节通过率与 5.6 节修复率综合判定：
- 通过率 ≥ 95% 且 Critical 全部修复 → **建议发布**
- 通过率 85%-95% 或存在 Major 未修复 → **有条件发布**（附修复计划）
- 通过率 < 85% 或存在 Critical 未修复 → **不建议发布**

### 8.2 下一步建议
1. **修复优先级**：按 5.5 节 TOP 5 缺陷清单先修 Critical / Major
2. **回归测试范围**：修复后回归对应模块全部 P0 用例 + 相关 P1
3. **自动化覆盖**：将 150 条用例中可自动化的部分（M2 阶段）
   - 接口用例 60% → pytest + requests
   - UI 主链路 30% → Playwright
   - 兼容性 10% → Playwright + BrowserStack
4. **持续集成**：GitHub Actions + Allure 报告（详见 M2-D8）
5. **监控告警**：上线后接 Prometheus + 业务异常告警
