# mall4j 业务全貌：B2C 单商户 + 三端合一 + 五流贯通

用户已能独立讲清 mall4j 的业务定位、三端架构与五流贯通含义，并能在面试场景下从项目文档抽出业务理解支撑测开论证，决定 M1 阶段继续按"业务理解 → 测试件"路径推进。

## 前置基础
- Java + Python 基础语法 / 接口测试基本概念（HTTP / JSON / 状态码）。
- 零电商项目实战、零实习经历；零 Sa-Token / Redisson / MyBatis-Plus 源码阅读经验。

## 本节收获
- mall4j = B2C 单商户电商开源版，前后台分离；一套后端服务三套前端（mall4v / mall4m / mall4uni）。
- 两个后端入口：`yami-shop-admin` (8085) 与 `yami-shop-api` (8086)，接口契约各管各的。
- 七大模块：商品/SKU、购物车、订单、支付、会员、权限、统计；不在开源版范围：营销/多商户/SaaS/跨境。
- 主链路：商品/SKU → 加购 → 确认订单 → 提交订单 → 支付 → 后台发货，6 个环节对应 5 类 Controller。
- 五流贯通 = 资金/信息/物流/配置/数据，孤立单点测试不写进用例库。
- 库存用 SQL 条件更新 `WHERE ? <= stocks` 防超卖；订单状态 1→2→3→4→5 失败归 6。

## 含义（用户能向面试官讲清楚什么）
- "我为什么选 mall4j"——业务真实、技术栈主流、文档完备、社区活跃、能在 14 天做出做深扛追问的作品集。
- "三端如何测"——两套后端各自维护一套接口用例集；Swagger UI 在 `localhost:8086/doc.html`。
- "什么是五流贯通"——任何测试用例都要落到资金/信息/物流/配置/数据流的交叉点。
- "主链路每个环节的关键设计"——确认订单缓存、库存条件更新、支付成功事件、定时任务（超时取消/自动收货）。
- "开源版边界"——营销/多商户/SaaS/跨境 不在本项目范围，被追问时直接说"开源版不支持"。
