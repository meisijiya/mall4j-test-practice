# 150 条用例拆解：五大方法 × CONTEXT 可测点 × 模块优先级

用户已能用 Python `csv.DictReader` 实测统计 D2 + D3 = 150 条用例的模块 / 设计方法 / 优先级 / HTTP 方法四个维度分布，并能用"五种方法 × 三轴分配"原则回答"为什么是 150 条不是 300 条"——这意味着 M1 阶段"测试设计方法 → 真实用例库"的链路打通，下一课直接进入 Postman 接口调试与完整链路。

## 本节收获
- **拆解三原则**：业务价值优先（P0 100% / P1 80% / P2 50%）+ 方法适配模块 + 不做无效叠加——这三条原则共同决定 150 条的总量。
- **五大方法真实落点**：等价类切枚举（D3 订单 6 状态 = 6 类）、边界值取阈值（D3 金额 0/0.01/999999.99）、场景法连主链路（D2 + D3 主链路 8 条 + 备选 79 条）、状态迁移 3 路径（每迁移正常 + 异常前置 + 幂等 = 27 条标称）、正交 L₉(3³)（D3 PERM-001/002 实证）。
- **实测统计数字**（来源：`test-cases/M1-D2-001/M1-D2-001-testcases.csv` + `test-cases/M1-D3-001/M1-D3-001-testcases.csv`，Python 统计）：
  - **按模块**：PROD 30 + ORDER 25 + CART 20 + COMPAT 20 + REG 12 + UPD 10 + SMS 10 + LOGIN 8 + ADDR 8 + MEMBER 5 + PERM 2 = 150
  - **按设计方法**：scenario 87（58%）+ boundary 41（27%）+ compatibility 12（8%）+ security 8（5%）+ concurrency 2（1%）= 150
  - **按优先级**：P0 67（45%）+ P1 63（42%）+ P2 20（13%）= 150
  - **按 HTTP 方法**：POST 69 + GET 47 + PUT 21 + DELETE 7 + MIXED 6 = 150
- **D2 vs D3 倾向差异**：D2 重主链路（P0 47 / P1 38 / P2 5），D3 重兼容与异常（P0 20 / P1 25 / P2 15）——两阶段方法论倾向不同。
- **状态机 3 路径法**：每迁移 × 3 路径 = 9 迁移 × 3 = 27 条标称；D3 实测 11 条状态机 + 6 条幂等 = 17 条相关用例（剩余 8 条 ORDER 用例覆盖主链路 / 并发 / 鉴权 / 参数 / SQL 注入）。
- **用例评审 10 条 Checklist**：覆盖完整 / 边界就位 / 异常路径 / 幂等覆盖 / 状态机完整 / 可执行性 / 数据驱动 / 优先级 / 可追溯 / 评审结论——150 条 × 10 维度 = 1500 检查点，半天跑完一轮。

## 含义（用户能向面试官讲清楚什么）
- "为什么是 150 条不是 300 条"：业务价值 × 方法适配 × 优先级三轴分配，不做方法叠加堆数。
- "150 条用例如何分布"：方法层 58% scenario + 27% boundary = 85% 字段+流程；异常层 14% 兜底；P0 45% 主导上线门禁。
- "状态机怎么写用例"：6 状态 × 3 路径 = 18 条；每迁移覆盖正常 / 异常前置 / 幂等三姿势。
- "等价类颗粒度怎么定"：按业务约束数切，不是按字符类型切。订单 6 状态 = 6 类。
- "正交实验怎么降维"：L₉(3³) 把 27 全组合降维到 9 条，每对因子每个水平组合恰好出现 1 次。
- "用例评审怎么打分"：10 维度 Checklist × 150 条 = 1500 检查点，半天跑完一轮。
- "D2 vs D3 倾向差异"：D2 重主链路（P2 仅 5 条），D3 重兼容异常（P2 占 15 条）。
