1. workflow 最小骨架（api-test.yml）

来源：.github/workflows/api-test.yml

name: API Test Pipeline
on:
  push:
    branches: [main, dev]
  pull_request:
    branches: [main]
  workflow_dispatch:
    inputs:
      RUN_UI:
        type: choice
        options: ["0", "1"]
        default: "0"
jobs:
  test_api:
    runs-on: ubuntu-latest
    timeout-minutes: 30
    steps:
      - uses: actions/checkout@v4

触发：push / PR 自动跑；手动 dispatch 走 RUN_UI=1 触发 UI 链路。AGPLv3 边界 100% 守：workflow 不动本体源码，依赖 target/*.jar 预编译产物。

2. services 块（MySQL8 + Redis7）

docker-compose 风格但写在 workflow 内，runner 自动起容器。

services:
  mysql:
    image: mysql:8.0.33
    env:
      MYSQL_ROOT_PASSWORD: ${{ secrets.MALL4J_DB_ROOT_PASSWORD }}
      MYSQL_DATABASE: ${{ secrets.MALL4J_DB_NAME }}
    ports: [3306:3306]
    options: >-
      --health-cmd="mysqladmin ping"
      --health-interval=10s
      --health-retries=5
  redis:
    image: redis:7.2-alpine
    ports: [6379:6379]
    options: --health-cmd="redis-cli ping" --health-interval=10s

健康检查：MySQL 等 mysqladmin ping 通才进 step；Redis redis-cli ping → PONG。超时默认 30s，retry 5 次后挂。

#动作关键参数

4. 5 个 secrets 清单

Settings → Secrets and variables → Actions 配置：

  • MALL4J_DB_ROOT_PASSWORD — MySQL root 密码（灌 DDL 用）
  • MALL4J_DB_NAME — 数据库名（默认 yami_shop）
  • MALL4J_DB_USER — 应用账号
  • MALL4J_DB_PASSWORD — 应用密码（java -jar 用 SPRING_DATASOURCE_PASSWORD 覆盖）
  • MALL4J_REDIS_PASSWORD — Redis 密码

注意：GITHUB_TOKEN 是 Actions 自动注入的，不要手动配；同理 RUN_UI 走 workflow_dispatch.inputs，不需 secret。

5. 6 件非显然 fix（CI 必踩的坑）

  1. skipif 顶层 load env — conftest.py 顶层调 _load_env()，否则 pytest collect 阶段 os.getenv('PROD_ID') 拿不到值 → 永远 skip。
  2. AES-ECB cryptography 双装 — pip 必须显式 cryptography + pycryptodome（mall4j AES-ECB-PKCS7 兼容）。
  3. cart/order 硬编码 ID — seed-data.sql 走 .github/workflows/，不依赖外部 fixture。
  4. chromium 默认 RUN_UI=0 — 150MB 不下，dispatch 才装（省 90% runner 流量）。
  5. allure-commandline 不在 pip — awesomecode/allure-action@v1 自动下二进制，不污染 Python env。
  6. CI 网络不切镜像 — runner 本就快，切 pypi.tuna 反而慢 + 易超时。

6. 降级路径 3 条

场景降级方案
allure-action 失败改 actions/upload-artifact@v4 上传 raw allure-results/，本地 allure generate。
chromium 下载失败env.RUN_UI == '0' 直接跳过整段 UI step，CI 仍绿。
mvn 编译失败actions/download-artifact@v4 拉 prebuilt jar（yami-shop-api-*.jar），跳过 step 6。

失败容忍原则：CI 红 ≠ 阻塞合并；只 FAIL 在测试断言本身才 block；环境/mvn/网络层失败走降级或重试（continue-on-error: true）。

7. 本地模拟 + 月度用量

run-ci.sh 一行命令（前提：服务已启、.env 已配）：

bash test-cases/api-auto/run-ci.sh

月度 runner 用量估算：

30 次推送 × 3 min/次 = 90 分钟 ≤ 2000 分钟免费配额（占 4.5%）

关键路径速查：

  • .github/workflows/api-test.yml — workflow 主体
  • docs/CI.md — secrets 配置 + 排错手册
  • test-cases/api-auto/run-ci.sh — 本地一行复刻 CI
  • doc/3-API接口/M2-D9-001-impl-notes.md — 实施笔记

离线 vs CI：CI 跑全链路（MySQL + Redis + mvn + pytest + allure）；本地跑只跑 pytest（服务 + .env 由用户侧保证）。两者同源 yaml 数据驱动，零代码差。
