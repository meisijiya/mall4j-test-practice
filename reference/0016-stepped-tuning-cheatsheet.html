§1 3 场景脚本

login / query / order × 4 阶梯 × 2 轮

  • login：HttpUser + on_start adminLogin + 3 @task view_prod_list 60% / detail 30% / my_info 10%
  • query：HttpUser 不登录 + 3 @task view_prod_list 50% / detail 30% / search_by_tag 20%
  • order：HttpUser + on_start adminLogin + 3 @task order_list 40% / order_detail 30% / cart_list 30%
  • 合计：3 场景 × 4 阶梯 × 2 轮 = 24 个 locust 实例

§2 4 阶梯设计

50 / 100 / 200 / 500 × 60s + 间隔 30s

  • 50u：基线（无压力）
  • 100u：D10 单点压测（参考线）
  • 200u：2 倍 D10（找拐点）
  • 500u：极限（单实例 Spring Boot 容易 OOM）

间隔 30s 不是闲等：JVM 缓存预热（HikariCP min-idle→maximum-pool-size ~10s）+ GC 触底（堆内存回落 ~5s）+ HikariCP 回收（超时连接 ~15s）

§3 调优决策树

TPS 不涨反降 / P99 > 2000ms 时怎么查？

1. CPU 100%?
   ├─ Yes → jstack 看线程 dump 有 BLOCKED?
   │       ├─ Yes → 锁竞争（❌ 改 Java 违反 AGPLv3）
   │       └─ No  → 线程池 200→400 ✅
   └─ No  → 内存 80%?
           ├─ Yes → GC 频繁?
           │       ├─ Yes → -Xmx1g + G1GC ✅
           │       └─ No  → 内存泄漏（❌ 改 Java 违反 AGPLv3）
           └─ No  → DB 连接池满?
                   ├─ Yes → HikariCP 10→30 ✅
                   └─ No  → Redis 连接池满?
                           ├─ Yes → Lettuce 6→20 ✅
                           └─ No  → 业务逻辑（❌ 改 Java 违反 AGPLv3）

§4 tuning-config.properties 关键 3 段

AGPLv3 不动 Java，调优全走 .properties

# 1. Tomcat 线程池（默认 200 → 400）
server.tomcat.threads.max=400
server.tomcat.threads.min-spare=50
server.tomcat.max-connections=10000

# 2. HikariCP 连接池（默认 10 → 30）
spring.datasource.hikari.maximum-pool-size=30
spring.datasource.hikari.minimum-idle=10
spring.datasource.hikari.connection-timeout=30000

# 3. Lettuce Redis 池（默认 6 → 20）
spring.redis.lettuce.pool.max-active=20
spring.redis.lettuce.pool.max-idle=10

§5 tuning-jvm.sh 应用方式

pkill + java -Xmx1g + G1GC + .properties

#!/usr/bin/env bash
set -euo pipefail
pkill -f "yami-shop-api.*\.jar" || echo "ℹ️ 无旧 java"

java -jar yami-shop-api/target/yami-shop-api-0.0.1-SNAPSHOT.jar \
    --spring.profiles.active=dev \
    --spring.config.additional-location=file:./tuning-config.properties \
    -Xmx1g -XX:+UseG1GC -XX:MaxGCPauseMillis=200 \
    > api.log 2>&1 &

echo "✅ 调优后 API 启动"
sleep 30
curl -s http://127.0.0.1:8086/doc.html > /dev/null && echo "✅ ready"

§6 run-stepped.sh 调度

4 阶梯 × 3 场景 × 2 轮 = 24 跑次

#!/usr/bin/env bash
set -euo pipefail
export GEVENT_BACKEND=select

STEPS="${STEPS:-50 100 200 500}"
INTERVAL="${INTERVAL:-30}"

# 调优前
for USERS in $STEPS; do
    for SCENARIO in login query order; do
        locust -f "locustfile_${SCENARIO}.py" \
            --users $USERS --spawn-rate 10 --run-time 60s \
            --headless --only-summary \
            --html reports/before/L$((USERS/50))-${SCENARIO}-report.html \
            --csv  reports/before/L$((USERS/50))-${SCENARIO}-stats
        sleep $INTERVAL
    done
done

# 调优重启
bash tuning-jvm.sh && sleep 60

# 调优后（同样 24 跑次输出到 reports/after/）
# ... 同上

python generate-stepped-report.py   # → reports/stepped-comparison.md
