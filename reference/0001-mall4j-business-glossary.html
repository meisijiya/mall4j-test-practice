1. 三端对照表

mall4j 是 B2C 单商户电商，一套后端服务三套前端。两个后端入口各管各的契约，接口自动化必须分别建用例集。

端后端模块端口调用方（前端）技术栈
管理后台yami-shop-admin8085front-end/mall4vVue3 + Vite + Element Plus + AVUE + Pinia
用户端（H5 / 小程序）yami-shop-api8086front-end/mall4m原生微信小程序 + H5
用户端（跨端）yami-shop-api8086front-end/mall4uniuni-app 跨端编译

Swagger UI：http://localhost:8086/doc.html（Knife4j）。前后端通过 /sys/menu/nav 动态加载菜单路由。

2. 七大模块速查

#模块源码路径职责

3. 核心交易链路（ASCII 流程图）

来源 doc/6-核心业务/1-核心交易链路.md。

+----------------+   +-----------+   +-----------+   +-----------+   +--------+   +----------+
|  商品 / SKU    |-->| 加入购物车 |-->| 确认订单   |-->| 提交订单   |-->|  支付   |-->| 后台发货 |
| ProdController |   | ShopCart  |   | Order     |   | Order     |   | Pay    |   | Admin    |
|  / SkuController|   | Controller |  | .confirm  |   | .submit   |   | Controller| | Order    |
+----------------+   +-----------+   +-----------+   +-----------+   +--------+   +----------+
       |                  |                |                |               |              |
       v                  v                v                v               v              v
    tz_prod            tz_basket   ConfirmOrderCache   tz_order +       tz_order_     tz_order.
  tz_sku            (uk_user_shop_sku)  (Redis)       tz_order_item    settlement   status 流转
   .actual_stocks                                          + 库存条件更新     pay_amount   (1->2->3->4->5)
   .stocks                                                WHERE ? <= stocks

关键节点：

  • 确认订单结果先入 ConfirmOrderCache，提交时读取。
  • 提交订单清理 ConfirmOrderCache + 购物车缓存。
  • 库存扣减用 SQL 条件更新 WHERE ? <= stocks 防超卖；失败清理商品/SKU 缓存并抛"库存不足"。
  • 支付成功发布 PaySuccessOrderEvent，后续逻辑事件订阅。

4. 五流贯通（一句话定义）

资金流（支付→结算→退款原路返回）、信息流（下单→后台看单→拣货）、物流（发货→签收）、配置流（后台配置→用户端生效）、数据流（订单/支付/会员→统计报表）——五条流在同一笔订单上同时跑通，单点通过的孤立测试不写进用例库。

5. 关键术语

SKU / SPU

概念定义存储表
SPU（商品）展示/售卖的抽象商品，含名称、主图、详情、分类、运费模板。tz_prod
SKU（规格）可购买的最小单元，含价格、库存、销售属性组合。tz_sku
规格 / 规格值如"颜色：红色 / 版本：64GB"。tz_spec / tz_spec_value

订单状态枚举（yami-shop-bean/.../enums/OrderStatus.java）

状态值含义触发动作
1待付款提交订单后写入；超时由 OrderTask 定时取消
2待发货支付成功触发
3待收货商家发货触发
4待评价用户确认收货
5成功用户评价完成（或超时）
6失败 / 关闭超时未付 / 用户取消 / 退款关闭

支付渠道

渠道开源版现状测试切入点
微信支付支付接口直接调 paySuccess()，无真实网关支付流水号生成 + 状态更新幂等
支付宝同上同上
余额同上同上
回调（PayNoticeController）当前代码为注释占位真实接入需补签名校验 + 幂等去重

多订单可共用一个 payNo（并单支付），金额从 tz_order_settlement.pay_amount 汇总读取，不接受前端传入金额。

库存扣减点

位置扣减时机SQL 关键条件
SkuMapper.xml提交订单时（数据库条件更新）WHERE sku_id = ? AND ? <= stocks
ProductMapper.xml同上（汇总层）WHERE prod_id = ? AND ? <= total_stocks
更新失败清理商品/SKU 缓存 + 抛"库存不足"异常——

返还时机：订单取消 / 退款关闭。配合 Redisson 分布式锁防并发超卖。
