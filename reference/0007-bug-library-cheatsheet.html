3. 5 大源码线索 checklist（预测缺陷的扫描器）

线索扫描动作典型 bug_id风险指纹
① 弱约束 Param 打开 Param 实体类，看字段注解：只有 @Schema 没有 @NotBlank/@Pattern/@Size → 风险 BUG-001 注册无格式校验 第 24-48 行字段全部仅 @Schema
② 鉴权链缺口 看 Controller 方法签名 + 方法体首行：无 @SaCheckLogin / SecurityUtils.getUser() → 风险 BUG-002 改密未鉴权 第 78-100 行 updatePwd 无注解
③ 状态机守卫 看 Order 实体是否有 @Version；状态变更 SQL 是否带 where version=? → 风险 BUG-014 取消状态机无乐观锁 第 139 行 Objects.equals + 无 version
④ 事务边界 看多个写操作是否同 @Transactional；Service 调用是否独立 → 风险 BUG-013 支付事务丢失 第 42-52 行 pay/paySuccess 独立调用
⑤ 缓存一致性 看写操作是否 @CacheEvict / removeCache；key 是否按 userId 等唯一分键 → 风险 BUG-005 商品缓存不一致 第 184-185 行仅在 cancel 清缓存

扫描顺序：Param 实体类 → Controller 方法注解 → 状态变更方法 + Entity → 写操作方法体 → 写操作后缓存代码。每扫到 1 个风险点 → 产出 1 条预测缺陷。

6. 修复建议常用注解速查

注解 / API所属框架作用典型用法
@NotBlank jakarta.validation 字符串非 null 且 trim 后非空 @NotBlank(message="手机号不能为空")
@Pattern jakarta.validation 正则校验字符串格式 @Pattern(regexp="^1[3-9]\d{9}$")
@Size / @Min / @Max jakarta.validation 长度 / 数值上下界 @Size(max=64) @Min(-999) @Max(999)
@Email jakarta.validation 邮箱格式校验 @Email(message="邮箱格式错误")
@SaCheckLogin / @SaCheckRole Sa-Token 方法级鉴权 @SaCheckLogin（已登录）/ @SaCheckRole("admin")
@PreAuthorize Spring Security 方法级鉴权（SpEL 表达式） @PreAuthorize("hasRole('ADMIN')")
SecurityUtils.getUser() mall4j 自封装 取当前登录用户上下文 方法首行强校验 userId
@Transactional Spring 声明事务边界 @Transactional(rollbackFor = Exception.class)
@Version MyBatis-Plus 乐观锁版本号字段 实体字段加 @Version Long version；updateById 自动带 where version=?
@CacheEvict / @Cacheable Spring Cache 缓存清除 / 读取 @CacheEvict(value="prod:", key="#prodId")
@TransactionalEventListener Spring 事务提交后异步事件 @TransactionalEventListener(phase=AFTER_COMMIT) 解决"先 DB 后缓存"
RedisLock.tryLock Redisson 分布式锁防并发 lockKey = "shopcart:sku:" + skuId，5 秒 TTL
