1. YAML Schema 5 字段（+ 3 可选）

来源：test-cases/api-auto/data/*.yaml + common/yaml_loader.py

字段类型必填说明
namestr是用例 ID / 描述，pytest 用例 ID 显示
descriptionstr是用例意图中文描述
paramsdict是请求参数（path / query / body），支持 {{var}} 占位
expected_codestr是业务码：'00000' / 'A00001' / 'A00004' / 'A00014'
prioritystr是P0 / P1 / P2，影响 allure 分级

可选字段：pre: { type: probe_sku } 跑前探针 / post: { type: write_basket_id } 跑后写回 / skipif: "PROD_ID not in env" 跳过条件

铁律：expected_code 必须用字符串（mall4j code 是 String，不是 Integer）。

2. substitute + SafeDict 用法

来源：test-cases/api-auto/common/yaml_loader.py §§{{var}} 模板替换

from common.yaml_loader import substitute, SafeDict
import os

# 1. 递归替换 dict / list / str 里的 {{var}}
mapping = {"skuId": "1101", "basketId": "8850"}
result = substitute({"basketId": "{{basketId}}", "skuId": "{{skuId}}"}, mapping)
# → {"basketId": "8850", "skuId": "1101"}

# 2. SafeDict 防 KeyError：缺 key 时返回 "{{key}}" 字面
sd = SafeDict({"skuId": "1101"})
"{{skuId}}/{{addrId}}".format_map(sd)
# → "1101/{{addrId}}"   # 不抛异常，留字面给下游 substitute 兜底

# 3. mapping 通常来自 os.environ（探针 write_env 写回）
mapping = dict(os.environ)  # 含 PROD_ID / SKU_ID / ADDR_ID / ORDER_NUMBER

签名：substitute(value: Any, mapping: Mapping[str, Any]) -> Any，递归处理 dict / list / tuple / str，其他类型原样返回。

pytest_yaml_cases：pytest_yaml_cases(yaml_path, key, *, env=None, substitute_vars=True) -> list[dict]，env 默认从 os.environ 读。

3. 探针 helper 三种（D5 v3.0 风格）

来源：common/yaml_loader.py §探针 helper

helper签名写回 key触发接口
probe_sku (api_client, prod_id=1, *, write_env=True) -> dict PROD_ID + SKU_ID GET /prod/prodInfo?prodId=1 + GET /sku/getSkuList?prodId=…
probe_addr (api_client, *, write_env=True) -> dict ADDR_ID GET /p/address/list 拿第一条 addrId
probe_order (api_client, *, write_env=True) -> dict ORDER_NUMBER GET /p/myOrder/myOrder 拿第一条 orderNumber

调用示例（在 yaml 的 pre 字段或 conftest fixture 里触发）：

from common.yaml_loader import probe_sku, probe_addr, probe_order, write_env

# 1. 显式调用（fixture 级）
def test_cart_add(api_client, env):
    probe_sku(api_client, prod_id=1, write_env=True)
    # os.environ 现在含 SKU_ID，下游用例 {{SKU_ID}} 自动替换

# 2. yaml 字段触发（cart_data.yaml / addr_data.yaml）
#   - name: cart_add_normal
#     pre: { type: probe_sku }
#     params: { skuId: "{{SKU_ID}}", basketCount: 1 }

# 3. 手动写回任意 key

设计要点：探针先调真实接口拿 ID → 写回 os.environ → 下游用例 {{SKU_ID}} 占位自动替换。与 D5 Postman v3.0 探针请求机制同源。

4. 业务码断言修复（test_prod.py 3 处 bug）

来源：D7 README §8 + common/assertion.py + common/api_helper.py

位置错误写法正确写法
test_prod.py::test_page_prod_default assert_business_code(resp, 200) assert_business_code(resp, "00000")
test_prod.py::test_get_sku_list assert_business_code(resp, 200) assert_business_code(resp, "00000")
test_prod.py::test_prod_info resp.code == 200 str(resp.code) == "00000"

assert_business_code 兼容实现（common/api_helper.py / common/assertion.py）：

def assert_business_code(resp, expected="00000"):
    body = resp.json() if hasattr(resp, "json") else resp
    actual = str(body.get("code"))
    expected = str(expected)
    assert actual == expected, f"业务码 {actual} != 期望 {expected}"

铁律：mall4j ServerResponseEntity.code 是 String（'00000'/'A00001'/'A00004'/'A00005'/'A00014'）。D6 漏改字符串 → pytest 默认 to.eql(200) 永远 FAIL；D7 已统一 str(expected) 强转。

yaml 端：expected_code 字段也用字符串，不要写 expected_code: 200，否则 pytest_yaml_cases substitute 后断言时类型失配。

5. Playwright 路径 1：API 拿 token + cookie 注入

来源：D7 README §5.1 + common/ui_pages.py::BasePage

核心思路：调后端 /login 拿 accessToken → Playwright context.add_cookies 注入 Authorization cookie → 跳首页验证路由。

def test_admin_login(page, api_client, env):
    from api.login_api import LoginAPI
    from common.ui_pages import BasePage
    import os

    # 步骤 1：API 拿 token（绕开前端 AES + 滑块）
    api = LoginAPI(api_client)
    resp = api.admin_login("admin", encrypt_password("123456"), sys_type="ADMIN")
    token = resp.json()["data"]["accessToken"]

    # 步骤 2：cookie 注入
    base = BasePage(page)
    admin_url = os.getenv("ADMIN_WEB_URL", "http://localhost:8085")
    base.inject_auth_cookie(token, admin_url)

    # 步骤 3：跳首页 + 等路由
    base.goto(admin_url + "/", timeout=5000)
    base.wait_for_url("/home", timeout=3000)
    base.screenshot("ui-evidence/test_admin_login.png")

优点：完全绕开滑块 + AES 加密；UI 用例只验证"cookie 注入 + 路由跳转 + 截图存证"。

缺点：UI 用例没有真正"走前端表单"——D8 才上路径 2（mock captcha + 真实填表 + page.route("**/adminLogin", lambda r: r.fulfill(...))）。

运行开关：需 RUN_UI=1 环境变量 + Playwright + dev server（mall4v 8088 / admin 8085）。dev server 未启时 page.goto 超时 → 截图存 <case>_fail.png + WARN 日志（不算硬 FAIL）。

6. 缺包优雅降级（conftest.py 顶层 + page fixture 双层）

来源：D7 README §5.3 + conftest.py

为什么是顶层：@pytest.mark.skipif 在 collect 阶段求值，那时 fixture 还没跑 → _HAS_PLAYWRIGHT 必须在模块顶层 import 之后立刻求值。

# conftest.py 顶层（关键 — 不在 fixture 内）
try:
    from playwright.sync_api import sync_playwright
    _HAS_PLAYWRIGHT = True
except ImportError:
    _HAS_PLAYWRIGHT = False

# session 级 browser fixture
@pytest.fixture(scope="session")
def _playwright_browser():
    if not _HAS_PLAYWRIGHT:
        pytest.skip("Playwright 未安装；UI 用例跳过。")
    if not os.getenv("RUN_UI"):
        pytest.skip("未设 RUN_UI=1，UI 用例跳过。")
    with sync_playwright() as p:
        browser = p.chromium.launch(headless=True)
        yield browser
        browser.close()

# 用例级 page fixture（双层兜底）
@pytest.fixture
def page(_playwright_browser):
    ctx = _playwright_browser.new_context()
    pg = ctx.new_page()
    yield pg
    ctx.close()

# test_ui_login.py 用例侧再补一道 skipif
@pytest.mark.skipif(not _HAS_PLAYWRIGHT, reason="playwright not installed")
@pytest.mark.skipif(not os.getenv("RUN_UI"), reason="RUN_UI not set")
def test_admin_login(page, api_client, env): ...

效果：未装 playwright 时 pytest --collect-only 仍 PASS；UI 用例 collect 时标 skip，不影响其他 52 条用例。

allure 同样思路：common/allure_compat.py 用 try/except import，未装 allure-pytest 时降级到普通 pytest 日志，--collect-only 不报错。

7. 验收命令 5 条（D7 收尾门禁）

来源：D7 README §9

  1. yaml 5+ 文件合法（pure Python，无 pytest 依赖）：

    cd test-cases/api-auto

    grep -n 'assert_business_code.*200' testcases/test_prod.py

    grep -E "^playwright==" requirements.txt
