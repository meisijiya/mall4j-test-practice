2. UI 路径 2 captcha mock 顺序（必须 goto 前注册）

来源：D8 README §5.2 + common/ui_pages.py::LoginPage L170-234

核心思路：拦截前端 /captcha/get + /captcha/check + /adminLogin 端点 → 返回 mock JSON → 跳过滑块交互 + 真实后端登录。

from common.ui_pages import LoginPage

def test_login_shop_path2(page, env):
    # 步骤 1：必须在 page.goto 之前注册 route
    LoginPage.mock_captcha_route(page)             # 拦截 **/captcha/**
    LoginPage.mock_login_response(page,
        mock_token="mock_admin_token_path2")       # 拦截 **/adminLogin + **/login

    # 步骤 2：用例侧实例化 + 跳转
    login = LoginPage(page)
    login.goto_login(port="shop")                  # http://localhost:8088/login
    login.fill_form("testuser", "pwd", port="shop")
    login.click_submit(port="shop")

    # 步骤 3：等路由跳转（mock 已返回 00000，前端走 router.replace）
    login.wait_for_login(timeout=5000)             # → URL 含 /home

关键约束：page.route(...) 必须在 page.goto(...) 之前调用，否则浏览器先发真实请求就来不及拦截（Playwright 文档规定）。

关键 fix #2：mock 的端点是 **/adminLogin（mall4v views/common/login/index.vue:118-127 的 http.post('/adminLogin', ...)），普通用户登录也走 /adminLogin，/login 是另一套遗留端点。代码里同时注册两个 page.route 兼容。

3. admin vs shop 双 selectors dict + port 参数切换

来源：LoginPage.selectors L127-140 + HomePage.selectors L243-257

dict 双层结构：外层 key = port（"shop" / "admin"），内层 key = 元素名（"username" / "password" / "submit" 等）。

class LoginPage(BasePage):
    selectors = {
        "shop": {                                   # 商城 mall4v 8088
            "username": 'input[placeholder="账号"]',
            "password": 'input[placeholder="密码"]',
            "submit": 'button.login-btn',
            "captcha_verify": '.verify-sub-area',
        },
        "admin": {                                  # 后台 admin-web 8085
            "username": 'input[placeholder="请输入用户名"]',
            "password": 'input[placeholder="请输入密码"]',
            "submit": 'button.el-button--primary',
            "captcha_verify": '.el-captcha',
        },
    }

    def fill_form(self, username, password, *, port="shop"):
        sel = self.selectors[port]                  # ← 关键：dict[port] 取子集
        self.fill(sel["username"], username)
        self.fill(sel["password"], password)

约定：商城 UI 走 mall4v（placeholder="账号" + 自研 Verify.vue 滑块），后台 UI 走 admin-web（placeholder="请输入用户名" + Element Plus el-captcha）。两套前端框架 + 视觉风格完全不同，必须双 selectors。

port 切换：业务方法接受 port: str = "shop" 参数，方法内 self.selectors[port]["xxx"] 取对应 selector；调用方传 port="admin" 即切到后台。

HomePage 同样模式：click_category(name, *, port="shop") 内有 if port != "shop": raise NotImplementedError("admin 端分类点击待实现")——admin 端分类点击未实现时主动抛错，避免静默走错 selector。

4. allure severity 5 helper（优雅降级）

来源：common/allure_compat.py L77-138

helper等价于语义
severity_blocker()severity(severity_level.BLOCKER)阻断：核心流程崩
severity_critical()severity(severity_level.CRITICAL)严重：主流程错误
severity_normal()severity(severity_level.NORMAL)普通：默认
severity_minor()severity(severity_level.MINOR)次要：UI 边缘问题
severity_trivial()severity(severity_level.TRIVIAL)琐碎：文案错字

用法（用例侧装饰器）：

    severity_normal, severity_minor, severity_trivial,
)

@severity_blocker()
def test_login_shop_path2(page): ...

@severity_critical()
def test_cart_checkout_path2(page): ...

@severity_normal()
def test_user_addr_list(page): ...

优雅降级（无 allure 时）：

# common/allure_compat.py 顶层
try:
    import allure as _real_allure
    _HAS_ALLURE = True
except ImportError:
    _HAS_ALLURE = False

def severity(level):
    if _HAS_ALLURE:
        return _real_allure.severity(level)
    return _identity_decorator(level)   # 未装 allure → identity no-op

铁律：所有 helper 必须从 common.allure_compat import，不要 直接 import allure——未装 allure-pytest 时会 ImportError 挂整个 collect。

动态 severity：dynamic_severity(level) 在 fixture 内调（如 conftest 根据 marker 设 severity），需要 allure runtime context，缺 allure 时静默 no-op。
